> **Today's big item:** Google released Gemini 4 Neon on 18 November, a mid-tier model that sits between the bigger Gemini 4 Carbon and the faster Gemini 4 Hydrogen. It targets coding, analysis and agent work, reads up to 1 million tokens at once, and costs $3 in / $15 out per million tokens. Google says it costs about 32% less per task than Carbon, and it is already live in the Gemini API and Google AI Studio.

## New model launches

- **Google releases Gemini 4 Neon**
  A mid-size Gemini 4 model for coding and agent tasks with a 1M-token context window (how much text it can read at once), priced at $3/$15 per million input/output tokens and available now in the Gemini API.
  https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-neon/

## New techniques / papers

- **How much memory should an agent get? It depends on the model**
  Short lessons mined from an agent's own past runs helped DeepSeek-V3.2 most when it got all 191 of them, but the weaker gpt-oss-120b scored better with a picked subset of about 29 (55.4% vs 51.2%), and the code ships in the open-source altk-evolve library.
  https://arxiv.org/abs/2611.26361

- **Load-test self-hosted LLM servers with real agent traffic**
  Replaying recorded agent traces gave far more realistic tests than public traces when sizing a self-hosted inference server, where real agent load reached only about 60% of the throughput public traces suggested, and the tools and a trace dataset are open-sourced.
  https://arxiv.org/abs/2611.25905

## Agent orchestration frameworks

- **Google ADK 2.15.0 removes the Visual Agent Builder and tightens MCP prompts**
  McpInstructionProvider no longer fills MCP (a standard way to plug tools into LLMs) prompt arguments from session state, so pass them explicitly, and dynamic instruction routing is now on by default (turn off with `ADK_DISABLE_DYNAMIC_INSTRUCTION_ROUTING=1`).
  https://github.com/google/adk-python/releases/tag/v2.15.0

- **LangGraph 1.2.23 and 1.2.24 fix how tools see graph state**
  Tool calls sent with `Send` now get the same state as a normal edge and `wrap_tool_call` state overrides now reach the tool (langgraph-prebuilt 1.1.3), so re-test code that relied on the old behaviour before upgrading.
  https://github.com/langchain-ai/langgraph/releases
