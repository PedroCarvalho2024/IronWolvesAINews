AI digest for 2026-11-13 — 7 items

> **Today's big item:** Anthropic published a study on 11 November showing that when each person in a group gets their own AI agent, the group often does worse than when one shared agent serves everyone. The agents stalled, overrode each other's requests and made claims they could not back up. Simple fixes, like naming one agent as team lead, helped, and three of the test environments are released as an open benchmark called MAMUBench.

## New model launches

- **BotPsy-0.8B: a tiny open model for tool calling**
  A 0.8B-parameter model built on Qwen3.5-0.8B under Apache 2.0, with GGUF files (a format for running models locally) included, that roughly doubles its base model's tool-calling scores and is small enough to run on a laptop or phone for simple agent tasks.
  https://huggingface.co/blog/qvac/botpsy

## New techniques / papers

- **Anthropic: one agent per user can make groups worse**
  In four simulated team settings, giving every user a personal agent led to worse group results than one shared agent, so if you build multi-agent systems, test for agents blocking or overriding each other and try a designated lead agent.
  https://alignment.anthropic.com/2026/worse-together

- **WikiTrace: agent memory that keeps its receipts**
  Instead of storing only short "lessons learned", this agent memory (notes an agent saves between tasks) links each lesson to the task result and steps that produced it, so the agent can check a lesson before trusting it.
  https://arxiv.org/abs/2611.14320

- **Weak agent models can still be good judges and teachers**
  Models that performed poorly when acting in ALFWorld and WebShop were good at judging whether each step helped, and using them as a teacher during training lifted a small Qwen2.5-1.5B agent from 72.8% to 82.9% success on ALFWorld.
  https://arxiv.org/abs/2611.17167

## Interesting GitHub repos

- **Huawei open-sources MACaQ for fast model quantisation**
  An Apache 2.0 tool for quantisation (shrinking a model by storing weights in fewer bits) that outputs 2–4-bit GGUF files for llama.cpp or 4-bit models for vLLM, and its authors say it quantised a 122B model in 64 minutes using 32.5 GB of GPU memory.
  https://github.com/huawei-csl/MACaQ

## Ontologies & knowledge graphs for AI

- **AutoOntic builds an ontology from plain text**
  When an LLM extracts a knowledge graph (facts stored as linked entities) from text, it usually ends up flat and messy, and this tool adds a proper type hierarchy and rules on top, which the authors say lifts graph-based retrieval to 88% accuracy on the MINE benchmark.
  https://arxiv.org/abs/2611.15467

## RAG / vector DB tooling

- **Hugging Face: train ColBERT models to survive 4x vector pooling**
  ColBERT-style retrievers (search models that store one vector per word) need lots of storage, and a new Sentence Transformers training loss lets you merge vectors to cut storage about 4x while keeping 97.8% of search quality instead of 94.6%, useful if RAG (feeding docs to an LLM) storage costs hurt.
  https://huggingface.co/blog/token-pooling
