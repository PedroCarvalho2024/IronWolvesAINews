AI digest for 2026-11-02 — 12 items

> **Today's big item:** DeepSeek open-sourced dsh-superagent, a research prototype of a coding agent that watches one GitHub repo and picks up work when an allowed person asks for it. One "router" agent reads incoming messages and hands each task to its own "worker" agent, which works in a separate session and folder and replies, for example with a pull request. It is MIT-licensed TypeScript built on DeepSeek Harness, but DeepSeek says it is not a product, and its workers run shell commands without asking for approval, so try it only in a sandbox.

## New techniques / papers

- **HyperRepair: get back the general skills a fine-tuned model lost**
  After LoRA fine-tuning (cheap training of small add-on weights) a model often gets worse at general tasks, and this add-on recovered 93.4% of the base model's general score while keeping 99.5% of the new domain skill.
  https://arxiv.org/abs/2610.41147

- **Tool search breaks when a request needs several tools**
  A comparison of six ways to pick tools from a large list (including 257 MCP tools) shows that most methods rarely find every tool a multi-step request needs, so test your tool retrieval on multi-tool queries, not just single ones.
  https://arxiv.org/abs/2610.41905

## Interesting GitHub repos

- **DeepSeek dsh-superagent: an always-on coding agent for one repo**
  A router agent splits incoming GitHub requests into tickets and gives each one to a separate worker agent, which is a useful design to study if you build multi-agent systems.
  https://github.com/deepseek-ai/dsh-superagent-prototype

## Ontologies & knowledge graphs for AI

- **PEEL: pull a taxonomy out of an existing embedding model**
  In Matryoshka embeddings (vectors whose first part is a usable shorter vector), shorter prefixes match broader categories, and a small probe on top builds a concept hierarchy from just a word list, with no documents.
  https://arxiv.org/abs/2610.41785

## RAG / vector DB tooling

- **Pre-process your docs so agentic RAG reads less**
  With an agent that searches on its own using plain BM25 or grep (keyword search), the authors found extra indexing did not raise accuracy, but a pre-built tree of claims and evidence cut query tokens by 38% on average.
  https://arxiv.org/abs/2610.41172

- **KITE: agent memory without a vector database**
  It stores past conversations under a controlled list of topics and turns each question into a lookup plan you can inspect, scoring 93.5% on LoCoMo (a long-chat memory test) with about 1.6k tokens of context per question.
  https://arxiv.org/abs/2610.41521

## AI security & compliance

- **SecPO: training a model to ignore prompt injection**
  A new training loss plus strong generated attacks cut attack success on AgentDojo (an agent attack test) from 78.8% to 8.8% for a Qwen3.6-27B model, and the code, data and model are public.
  https://arxiv.org/abs/2610.41998

- **MCP tool calls can reveal who the user is**
  Using only an agent's tool calls and results, without the chat itself, attacker models guessed user profile details 26% of the time versus 18% by informed guessing, which matters for GDPR (EU data privacy law) when you log or share tool traces.
  https://arxiv.org/abs/2610.41885
