> **Today's big item:** Liquid AI released LFM3, a family of small open-weights models of about 2B parameters for text, vision and audio. The text model reads up to 256K tokens and fits in about 1 GB of memory at 4-bit (compressed weights), so it can run on a laptop or phone. Liquid AI reports it leads its comparison set on tool-calling benchmarks, which makes it worth a look for local agents.

## New model launches

- **Liquid AI releases LFM3, small open models for on-device agents**
  Six ~2B open-weights models (text, vision, audio, omni and decision) built on one base model, each fine-tunable on a single GPU and available on Hugging Face.
  https://www.liquid.ai/blog/lfm3

## New techniques / papers

- **Your agent harness may be silently cutting tool output**
  A study found one agent's harness (the code around the model) cut a third of tool results at a fixed length, breaking the JSON and hiding evidence, and two of seven popular frameworks cut output the same way.
  https://arxiv.org/abs/2610.36114

- **GEPA-Curator: better prompt tuning for agents by picking what to learn from**
  It improves GEPA (a tool that rewrites prompts from failed runs) by skipping noisy failures and showing past successes, with gains of up to 20.7% over GEPA on four agent benchmarks.
  https://arxiv.org/abs/2610.37651

## Ontologies & knowledge graphs for AI

- **OA-RAG: answering questions with an ontology plus an LLM**
  The agent mixes logic rules from an ontology (a formal map of concepts and their links) with LLM reasoning and tells you which facts it used and how strongly they back the answer.
  https://arxiv.org/abs/2610.36335

- **A knowledge graph of business processes helps agents call APIs in the right order**
  Storing endpoints, their order and their allowed values in one graph let an agent finish 38.7% of multi-step enterprise API tasks, against 10.3% with plain chunk-based RAG (feeding docs to an LLM).
  https://arxiv.org/abs/2610.37242

## RAG / vector DB tooling

- **QESChunker: learn where to split your documents**
  It picks chunk boundaries (where docs are split into pieces) by optimising against example question-and-evidence pairs instead of fixed sizes, and found the full evidence more often than existing chunkers on five datasets.
  https://arxiv.org/abs/2610.36557

- **Old facts in agent memory hurt more than unrelated text**
  When memory held both an old and a new version of a fact, accuracy fell from 100% to 44.6% for Qwen2.5-7B, so delete or mark outdated memories instead of just retrieving more.
  https://arxiv.org/abs/2610.36308

## Agent orchestration frameworks

- **CrewAI 1.15.31 patches several security bugs**
  It fixes path traversal, SQL injection and unsafe deserialization bugs and stops sending the `stop` parameter to GPT-6 and newer models, so upgrade if you run CrewAI in production.
  https://github.com/crewAIInc/crewAI/releases/tag/1.15.31

- **Pydantic AI 2.63 adds loop detection for agents**
  A new `DetectLoops` capability stops an agent that keeps repeating the same action, but read the compatibility notes first because several defaults changed, including Code Mode's tool catalog.
  https://github.com/pydantic/pydantic-ai/releases/tag/v2.63.0

## AI security & compliance

- **Heads of Security: attention gates that resist prompt injection**
  Small learned gates teach the model to read untrusted text without obeying hidden instructions in it, and a strong black-box attack succeeded 10% of the time against it versus 97% on plain GPT-OSS-20B.
  https://arxiv.org/abs/2610.37657

- **Log-To-Leak: poisoned MCP tools that leak your data after the task**
  A malicious MCP (Model Context Protocol, a standard way to give agents tools) tool description makes the agent send the user's query and tool results to the attacker after finishing the real task, working 62% to 100% of the time.
  https://arxiv.org/abs/2610.36108
