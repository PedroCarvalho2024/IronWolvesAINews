## New techniques / papers

- **SplitBench stops coding agents from faking benchmark passes**
  It runs the agent's tests in one place and judges the results in a trusted grader that holds the answers, matching native graders on 98.7% of attempts and blocking 75% of deliberate cheating, which matters if you trust agent benchmark (standard test suite) scores.
  https://arxiv.org/abs/2611.27860

- **Valid JSON is not the same as a correct answer**
  A 5,400-run comparison of structured output across PydanticAI, LangGraph, DSPy, CrewAI, Agno and a plain SDK found PydanticAI, LangGraph and DSPy stayed near 100% schema-valid with 0.91–0.94 quality, while the others scored lower, so check content, not just the schema.
  https://arxiv.org/abs/2611.27106

## Ontologies & knowledge graphs for AI

- **AutoOntologyBench tests whether agents can build useful ontologies**
  On about 20,000 tasks, ontologies (formal maps of concepts and links) built by agents added 6.1 points of task success on top of plain retrieval but stayed 13 points behind expert-built ones, and the code is on GitHub.
  https://arxiv.org/abs/2611.27734

- **GRACE shows why GraphRAG answers go wrong**
  A 4,028-question Wikidata benchmark for GraphRAG (RAG over a knowledge graph) that breaks evidence paths or adds distractors on purpose, so you can see whether failures come from missing facts or misleading ones.
  https://arxiv.org/abs/2611.27350

## AI security & compliance

- **A rules file in your repo does not stop a coding agent**
  A study of Claude Code, Codex CLI, Gemini CLI and OpenCode found a markdown rules file acted only as advice and even cut Codex CLI's hidden-test pass rate from 99% to 68%, while a network gate blocked every forbidden request.
  https://arxiv.org/abs/2611.27112

- **Synonym swaps can quietly poison a RAG knowledge base**
  Swapping words for synonyms in a security RAG (feeding docs to an LLM) corpus dropped answer correctness from 0.71 to 0.56, and a word-level entropy check (how surprising a word is) caught the edits with 0.95 AUROC (detection accuracy score).
  https://arxiv.org/abs/2611.27410

- **Correct past decisions can push small agents into breaking policy**
  After a small on-device agent correctly releases one item, it becomes more likely to wrongly release the next restricted item, seen across 13 open-weight models, and a LoRA (small add-on weight update) fix restored safe behaviour to nearly 100%.
  https://arxiv.org/abs/2611.27216
